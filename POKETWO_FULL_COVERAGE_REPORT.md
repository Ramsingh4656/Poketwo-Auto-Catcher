# Pokétwo Full-Coverage Detector Report

**Status:** The project now ships a **936-label full metadata-coverage detector**. It does **not** claim that all 936 labels have independently captured Discord-render test evidence. The independent real-render test covers **839 labels**; **97 labels are reference-only** because no verified real Pokétwo render was found in the acquired licensed capture sources. Those 97 labels are not represented as independently validated high-accuracy classes.

## 1. Authoritative class universe

The authoritative local snapshot is the official Pokétwo data repository metadata at [`poketwo/data`](https://github.com/poketwo/data), specifically `csv/pokemon.csv`. The inventory is generated by `scripts/inventory_forms.py` and stored in `reports/current_poketwo_inventory.json`.

| Measure | Count | Interpretation |
|---|---:|---|
| Metadata rows | 1,743 | Rows in the checked-out official metadata snapshot |
| Enabled rows | 1,659 | Rows marked enabled |
| Enabled and catchable records | **936** | Complete candidate class universe used by this release |
| Unique catchable slugs | **936** | No duplicate class slugs in the snapshot |
| Catchable rows flagged `is_form` | 196 | Includes regional, Mega, alternate, seasonal, and other form records according to metadata |
| Catchable rows with gender-difference capability | 75 | Capability flag; not every gender difference is necessarily a separate spawn label |
| Catchable rows with mega-linked fields | 28 | Metadata linkage requiring form rules and visual inspection |

The release uses the official metadata rows as the label universe rather than guessing from species counts. Official base and shiny reference assets are available for every one of the 936 records. Shiny files are retained as references, but the Pokétwo spawning documentation indicates shiny status is determined after catch and is not a separate pre-catch image class; therefore the pre-catch classifier does not double the class count merely because shiny files exist.

## 2. Acquired data and provenance

The complete training manifest combines automatically labeled official Pokétwo reference assets with the larger Apache-licensed Pokétwo spawn-image source.

| Source | Records/images used | Classes represented | Role |
|---|---:|---:|---|
| Official Pokétwo reference assets | 1,872 | 936 | Automatically labeled base/shiny reference coverage; not independent Discord evidence |
| Apache-licensed Kaggle Pokétwo spawn archive | 19,297 valid images | 839 | Real-render train/validation/test source |
| **Combined full manifest** | **21,169** | **936** | Full label universe for training |

The Kaggle archive was independently audited before use. Its complete archive contained 1,472 labeled folders and 33,856 images. After exact metadata matching, image validation, and manifest construction, 19,297 valid real-render images remained across 839 official labels. The manifest contains no exact duplicate hashes across the split partitions after the leakage controls were applied. Source-group and class-aware split rules are implemented in `scripts/prepare_full_manifest.py`.

The existing CC0 capture release remains retained as historical baseline data and is not silently mixed into the new independent test. The official transparent assets are not counted as real Discord-render evidence. Sources without clear redistribution rights or provenance, including the unlicensed SmartGuy09 archive and the Hugging Face mirror without a visible dataset card/license, were not used as training evidence.

## 3. Training protocol

The trained model is a pretrained **MobileNetV3-small** with a 936-output classifier head. Official transparent assets are composited onto a neutral background during loading rather than being converted to black. Captured RGB renders retain their original appearance. The backbone is frozen for the CPU-oriented experiment, and augmentation is applied only to training records.

The leakage controls are as follows. Exact duplicate hashes are removed across partitions; source groups are assigned before splitting; official references and captured renders are tracked separately; validation and test rows are never used for optimization; and the independent real-render test is restricted to labels with captured-image evidence. Synthetic augmentation is not used to claim missing real classes.

The full independent real-render test contains **3,356 images from 839 labels**. The 97 reference-only labels have no independent real-render test support in the acquired sources and therefore cannot honestly receive a real-render accuracy claim.

The overall metrics include every real-render test image and do not discard low-confidence cases. The accepted metrics report the operational behavior after abstention: only predictions at or above 0.30 are sent to the catch command, and the remainder use the Pokétwo hint fallback. No 100% accuracy claim is made.

### Hard-case evaluation

The hard-case suite applies brightness, contrast, blur, JPEG-like degradation, crop, dark-UI, and light-UI transformations to the independent real-render test. These are robustness probes, not additional independent captures.

| Hard-case measure | Result at cutoff 0.30 |
|---|---:|
| Total transformed samples | 26,848 |
| Accepted top-1 | **97.6898%** |
| Accepted macro precision | **87.2891%** |
| Accepted macro recall | **85.9147%** |
| Accepted macro F1 | **86.2664%** |
| Fallback rate | **33.5742%** |

The most difficult measured transformations were crop, with accepted top-1 of 92.8668%, and high brightness, with accepted top-1 of 97.4691% and a 47.0203% fallback rate. This is preferable to silently guessing on degraded images.

The complete per-class file is `reports/experiments/full_mobilenet_v3_small_frozen_fast/evaluation_full/per_class.csv`. It reports support, correct predictions, per-class accuracy, and whether each class has independent test evidence. The 97 reference-only labels have `independent_real_tested=false` and no real-render accuracy value.

## 5. Deployment and fallback policy

The integrated predictor loads `model/poketwo_detector_full/pokemon_detector.onnx` through ONNX Runtime on CPU and verifies that the output dimension matches the 936-label metadata file. The model export was verified with CPU execution and numerical agreement against the PyTorch checkpoint: maximum absolute logit difference was approximately `6.26e-06`.

The deployed default confidence threshold is **0.30**, selected from held-out threshold analysis. At this cutoff, accepted real-render predictions had 98.8871% top-1 accuracy while 25.0298% of test images abstained. An uncertain prediction returns `None`; `bot/bot.py` then waits for and uses the Pokétwo text hint. The bot does not issue a catch command for a below-threshold visual prediction.

The deployment configuration is `model/poketwo_detector_full/deployment_config.json`. The reproducible standalone inference entry point is `scripts/infer.py`. Training, evaluation, export, threshold analysis, per-class reporting, and dataset acquisition scripts are included under `scripts/`.

## 6. Unsupported and partially supported coverage

| Coverage category | Count | Status |
|---|---:|---|
| Full model labels | 936 | Automatically labeled and included in the trained model |
| Independent real-render tested labels | 839 | Real-render accuracy is measured for these labels |
| Reference-only labels | 97 | Official reference assets exist, but no verified licensed independent render was found |
| Unverified labels | 0 | No metadata label is silently omitted from the model |

The 97 reference-only labels include rare visual variants such as Alcremie sweets, Burmy, Deerling/Sawsbuck seasons, Unown letters, Vivillon patterns, Furfrou trims, Rotom devices, and other special forms identified by the coverage matcher. They are **not** reported as independently validated Discord-render classes. When the model is uncertain on these or any other image, the hint fallback is authoritative.

## 7. Reproducibility

From the repository root, install runtime dependencies with `python -m pip install -r requirements.txt`. Acquire the documented sources with `python scripts/download_dataset.py` and, where storage permits, `python scripts/download_kaggle_full.py`. Validate and construct the manifest with `python scripts/prepare_full_manifest.py`. Train with `python scripts/train.py --manifest reports/full_coverage/full_manifest.csv --data-root . --arch mobilenet_v3_small --output-dir reports/experiments/full_mobilenet_v3_small_frozen_fast --epochs 6 --batch-size 256 --lr 3e-4 --workers 0 --freeze-backbone`. Export with `python scripts/export_model.py`, verify with `python scripts/verify_export.py`, and evaluate with `python scripts/evaluate.py`.

The raw datasets and checkpoints are intentionally excluded from the GitHub-ready ZIP. The downloader and all provenance/manifests required to reproduce the process are included.
